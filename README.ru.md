# claude-delayed-message — отложенные сообщения для Claude Code

**Поставьте сообщение в очередь для своей сессии Claude Code — оно будет доставлено сразу после сброса лимитов использования или в выбранное вами время.**

Вы упёрлись в лимит использования Claude в 23:00. Лимиты сбрасываются в 2:00 — пока вы спите. Без этого инструмента следующее 5-часовое окно лимита начнётся только тогда, когда вы напишете первое сообщение утром. С ним — отложенное сообщение отправится в 2:00, сессия продолжит работать, и к вашему возвращению *следующий* сброс уже будет на несколько часов ближе.

> [English](README.md) · Русский

Разработка ведётся при поддержке [infilarite](https://infilarite.com/).

## Установка (2 команды)

```bash
npm install -g claude-delayed-message
cdm install
```

`cdm install` регистрирует лёгкую фоновую проверку (Windows Task Scheduler / macOS launchd / systemd timer или cron на Linux — раз в 10 минут) и устанавливает скилл `/delay` в `~/.claude/skills/`. Также он определяет абсолютный путь к бинарнику `claude`, чтобы запланированная задача находила его даже без PATH вашей оболочки.

## Используйте прямо из любого чата Claude Code

```
/delay Continue the refactoring we discussed: extract the parser into its own module
```

> Queued [a1b2c3d4] — will be sent to this session as soon as your usage limits reset.

```
/delay at "tomorrow 9:00" Run the test suite and summarize failures
/delay list
/delay edit a1b2c3d4 Continue the refactoring, but start with tests
/delay cancel a1b2c3d4
```

Или прямо из терминала:

```bash
echo "Continue where we left off" | cdm add --project C:\work\my-app
cdm list
cdm log
cdm status
```

## Как это работает

```
/delay  ──►  queue (~/.claude-delayed-message/queue/*.json)
                         ▲
OS scheduler (every 10 min) ──►  cdm run-once
        ├─ queue empty        → exit (no probe, zero cost)
        ├─ "at" items due     → deliver now
        └─ "limits-reset" items:
             probe (tiny haiku request)
             ├─ limit error   → free; remember expected reset time, wait
             └─ success       → limits are back: deliver everything FIFO
                                 via  claude --resume <session> -p  (stdin)
```

- Сама постановка в очередь выполняется **локальным хуком** (`UserPromptExpansion`) — `/delay` работает даже при полностью исчерпанных лимитах: для добавления в очередь ход модели не нужен.
- Зондирующий запрос **бесплатен, пока вы ограничены** (отклонённые запросы ничего не расходуют), а когда лимиты вернулись, стоит доли цента — и в этот же момент сразу отправляется ваше настоящее сообщение.
- Досрочные сбросы (Anthropic иногда сбрасывает лимиты всем раньше расписания) обнаруживаются в течение одного тика проверки.
- Доставка продолжает **ту же самую сессию** по её ID, так что просто откройте чат и продолжайте с того места, где остановились.

## Команды

| Команда | Что делает |
|---|---|
| `cdm add -m "<text>" [--at "<time>"] [--session auto] [--project <dir>]` | Поставить сообщение в очередь (текст также можно передать через `--message-file` или stdin) |
| `cdm list` | Показать очередь |
| `cdm edit <id> [-m "<text>"] [--at "<time>"] [--on-reset]` | Изменить ожидающий элемент |
| `cdm cancel <id>` | Отменить ожидающий элемент |
| `cdm log` | История доставок |
| `cdm status` | Состояние планировщика, определённый путь к `claude`, время последней проверки, размер очереди |
| `cdm install` / `cdm uninstall` | Зарегистрировать/удалить планировщик и скилл `/delay` |

Форматы времени для `--at`: `09:00`, `tomorrow 9am`, `tomorrow 12:30pm`, ISO вида `2026-07-08T09:00`. Если указано просто `ЧЧ:ММ` и это время сегодня уже прошло, оно переносится на завтра.

## FAQ

**Зондирующий запрос тратит мои лимиты?** Пока вы ограничены — нет, отклонённые запросы бесплатны. Когда лимиты доступны, зонд — это один крошечный запрос к haiku, и он выполняется только тогда, когда в очереди что-то есть.

**Какие права получает доставленный запуск?** Ровно те, что разрешены настройками Claude Code для этого проекта. Инструмент никогда не добавляет флаги прав (никогда не используется `--dangerously-skip-permissions`).

**Какую сессию выбирает `--session auto`?** Самую недавно активную сессию Claude Code для этой директории проекта. Если вы одновременно запускаете несколько сессий для одного и того же проекта, укажите явный `--session <uuid>` (UUID виден в списке выбора `claude --resume`), чтобы сообщение попало в нужный чат.

**Где хранятся мои данные?** Обычный JSON в `~/.claude-delayed-message/`. Тексты ваших сообщений хранятся там в открытом виде — относитесь к этой папке соответственно.

**Приложение было закрыто в момент отправки сообщения — я потерял ответ?** Нет. Файл сессии общий; откройте чат в Claude Code, и новый ход диалога будет там.

**Ничего не доставляется — как узнать почему?** Выполните `cdm status`. Если там ошибка зонда с `401` / `Failed to authenticate` — истёк логин **standalone CLI** (десктоп-приложение обновляет свой токен само, CLI — нет): откройте любой терминал, выполните `claude` и залогиньтесь — очередь продолжит работу на следующем тике автоматически. При этой ошибке также приходит уведомление на рабочий стол.

**Как удалить?** `cdm uninstall` удаляет запись планировщика и скилл; папка с данными остаётся.

## Access-токен CLI (прочитайте один раз)

Зондирование и доставка идут через **standalone CLI `claude`** в headless-режиме. Его access-токен — отдельный от десктоп-приложения Claude Code:

- Десктоп-приложение обновляет свой токен автоматически — вы можете неделями работать как обычно, пока токен CLI давно истёк.
- Headless-режим (`claude -p`) **не** обновляет истёкший токен — он падает с `401 Invalid authentication credentials`.
- `claude auth status` может показывать `loggedIn: true` даже с истёкшим access-токеном — не полагайтесь только на него.

**Обновление:** выполните `claude auth login` в любом терминале и завершите вход через браузер. Очередь продолжит работу на следующем тике автоматически — больше ничего делать не нужно.

**Контроль свежести:** вручную следить не нужно. На первом же сбойном тике придёт уведомление на рабочий стол, а `cdm status` покажет ошибку зонда с пометкой `[AUTH]` (напоминание примерно каждые 6 часов, пока проблема не решена). Кроме того, `cdm status` печатает срок действия токена — устаревание видно заранее, до поломки.
